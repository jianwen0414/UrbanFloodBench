URBAN FLOOD MODELLING: THE PROJECT BIBLE1. EXECUTIVE SUMMARY & MISSIONProject Codename: Twin-Engine Hydra
Objective: Build an AI-powered "Digital Twin" of a coupled urban hydraulic system to predict flood water levels autoregressively.The Core Challenge: We are modeling a Heterogeneous Graph where 1D underground pipes interact with 2D surface terrain. The system must simulate the St. Venant Equations (Conservation of Mass & Momentum) using Deep Learning. The primary difficulty is Autoregressive Instability: predicting $t+1$ using predictions from $t$ leads to compounding errors that can "explode" over long forecast horizons.The Winning Strategy: A "Multi-Fidelity Ensemble" approach. We reject the "one-size-fits-all" model in favor of decoupled, physics-aware experts. This strategy is directly derived from organizer hints ("Separate gets better results" and "Simple data is better").The Model PortfolioTier 0 (Baseline): XGBoost Regressor. A tabular approach to establish a robust "Score to Beat."Tier 1 (Twin Engines - Primary):Engine A (1D): GCN-GRU. Specialized for high-speed, pressurized pipe flow.Engine B (2D): GraphSAGE-GRU. Specialized for slow, diffusive surface spread.Tier 2 (Fallback): Unified HeteroGNN. An explicitly coupled model to capture complex surcharge events if the Twin Engines fail.2. COMPETITION INTELLIGENCE & RULESOfficial OverviewGoal: Accurately predict water levels for all 1D and 2D nodes across multiple rainfall events.Context: Urban flooding arises from complex interactions between underground drainage (1D) and surface overland flow (2D).Dataset Source: Two different urban models (Model 1 and Model 2) with distinct terrains and networks. The model must generalize across these different graphs.Timeline & PrizesDeadline: 1 March 2026, 11:59 PM (SGT).Private Leaderboard: Released 6 March 2026.Total Prize Pool: 9000 SGD (1st Place: 3500 SGD).The Critical Metric: Standardized RMSEWe are NOT minimizing standard MSE. The competition uses a variance-weighted metric to prevent models from ignoring "quiet" nodes. This change was implemented mid-competition to replace NSE (Nash-Sutcliffe Efficiency) due to low-variance instability.The Formula:$$\text{Score} = \text{Mean}_{\text{models}} \left( \text{Mean}_{\text{events}} \left( \text{Mean}_{\text{node\_types}} \left( \text{Mean}_{\text{nodes}} \left( \frac{\text{RMSE}_{i}}{\sigma_{i}} \right) \right) \right) \right)$$The Trap (Mathematical Pitfall):Node A (Flood Zone): High variance ($\sigma=2.0$). An error of 0.1ft is negligible ($0.1/2.0 = 0.05$).Node B (Dry Zone): Low variance ($\sigma=0.002$). An error of 0.1ft is catastrophic ($0.1/0.002 = 50.0$).Implication: Our Loss Function MUST be weighted by $1/\sigma^2$. If we use vanilla MSE, the model will focus on flood zones and ignore dry zones, destroying our leaderboard score.Submission RequirementsFile Format: Single CSV or Parquet file.Columns (Strict Order): row_id, model_id, event_id, node_type, node_id, water_level.Constraint: You must predict for both urban models, all test events, and all node types.Validation: A script checks for missing IDs. Incomplete submissions are rejected.Test Set Structure (The "Warm Start")Spin-up Period ($t=1 \dots 10$):Provided: Full Ground Truth for all dynamic variables (Water Level, Flow, Velocity, Rain).Action: Use these to initialize the hidden states ($h_t$) of the RNN/GRU.Scoring: These steps are NOT scored.Prediction Period ($t=11 \dots End$):Provided: ONLY Rainfall ($R_t$).Action: You must use your model's own prediction from $t-1$ to generate the input for $t$.Scoring: These steps determine the leaderboard ranking.3. DEEP DIVE: THE PHYSICS OF THE DATASETDomain 1: The 1D Underground (Pipes)Nodes: Manholes, Junctions, Inlets.Edges: Pipes (Channels).Physics: Water flows under pressure or gravity. Flow is fast and directional. Can reverse direction (backwater effect).Critical Physical States:Free Surface Flow: Pipe is partially full. Gravity driven.Surcharge: Pipe is full. Pressure driven. Water level exceeds pipe diameter.Flooding: Hydraulic Head > Surface Elevation. Water exits the manhole.Domain 2: The 2D Surface (Terrain)Nodes: Mesh cells (Triangular/Rectangular grid).Edges: Adjacency between cells.Physics: Water spreads via diffusion and gravity. Flow is slow and diffusive. Accumulates in depressions (sinks).Critical Physical States:Inundation: Depth of water on the ground.Runoff: Rain accumulating and flowing downhill.The Coupling (1D-2D Interaction)Drainage (Inlet Flow): Rain falls on 2D nodes $\to$ flows via gravity $\to$ enters 1D network at Inlets.Surcharge (Flooding): 1D pipe fills up $\to$ Hydraulic Head exceeds Surface Elevation $\to$ Water erupts onto 2D nodes.Note: In our Twin-Engine plan, this is modeled via a "Distance to Nearest Drain" feature. In the Unified fallback, it is an explicit graph edge.4. DATASET ENCYCLOPEDIA & ATTRIBUTE DICTIONARYThe dataset is strictly organized by Model (City) and Event (Rain). TECHNICAL PROTOCOLS1. The Metric Hack (Loss Function)To win, we must hack the metric.def standardized_rmse_loss(pred, target, node_stds, clamp_weights=100.0):
    # 1. Squared Error
    mse = (pred - target) ** 2
    # 2. Weight by Inverse Variance (Organizer's Metric)
    weights = 1.0 / (node_stds ** 2 + 1e-6)
    # 3. Clamp Weights (The "Explosion" Fix for dry nodes)
    weights = torch.clamp(weights, max=clamp_weights)
    # 4. Weighted Mean
    loss = (mse * weights).mean()
    return loss
2. Curriculum Learning (Scheduled Sampling)To solve Autoregressive Drift, we change the input source during training:Epoch 0-10 (Teacher Forcing): Input = Ground Truth $y_{t-1}$.Epoch 11-40 (Weaning): Linearly decay probability of using Ground Truth from 1.0 -> 0.0.Epoch 41+ (Student Forcing): Input = Model Prediction $\hat{y}_{t-1}$.3. Event-Based ValidationNEVER split data randomly. We use Leave-One-Event-Out cross-validation.Train: Events 1, 2, 3.Val: Event 4.Reason: We must test generalization to new rainfall patterns, not just interpolate missing time steps.4. Push-Forward TrainingWe do not calculate loss on just $t+1$. We run a sequence (e.g., 10 steps) and calculate loss on the entire trajectory.
$$ Loss = \sum_{k=1}^{10} \text{StandardizedRMSE}(\hat{y}{t+k}, y{t+k}) $$
This explicitly penalizes the model for "drifting" away from the true trajectory over time.
